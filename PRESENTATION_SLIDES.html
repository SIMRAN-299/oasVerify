Transforming raw OpenAPI Specifications into stateful, self-healing, CI/CD-ready PyTest suites using a Hybrid Declarative Architecture.

❌ Why Traditional & Pure-LLM Testing Fails

  • Manual Authoring Drag: Writing stateful E2E API tests takes days of engineering time per microservice.
  • Pure LLM Codegen Hallucinates: Asking an LLM to write raw pytest directly produces broken imports, lost variable state across steps, and brittle assertions.
  • Spec-to-Server Drift: Generated tests fail immediately on live servers due to undocumented regexes, enums, or 400 vs. 422 status differences.

✅ The OASVerify Breakthrough ("Rails + Brain")

  • Deterministic Rails: Kahn's Topological DAG ordering, strict Pydantic contracts, AST regex synthesis, and a zero-dependency Python compiler.
  • Gemini 3.8 Flash Brain: Domain-aware multi-step journey synthesis (Happy Path, Boundary Negative, Security, Idempotency) with {{variable}} chaining.
  • Live Dual-Mode Self-Healing: Diagnoses live HTTP 4XX rejections, hot-patches tests without weakening happy-path assertions, and verifies via instant re-run.

Deep Dive #1: Intelligent Planning

Topological DAG Ordering & Stateful Variable Chaining

How OASVerify solves multi-step foreign-key dependencies across API endpoints.

🕸️ Kahn's Topological Dependency Graph (graph.py)

  • APIs have strict state dependencies: you cannot call GET /products/{id} or POST /orders before creating the prerequisite resources.
  • DependencyGraph analyzes path hierarchies and HTTP verbs to construct a Directed Acyclic Graph (DAG):
    POST (Producer) ➔ GET (Reader) ➔ PUT/PATCH (Mutator) ➔ DELETE (Destructor)
  • Guarantees that destructive DELETE or cancel steps are always placed at the end of a journey.

🛡️ Deterministic Post-Generation Guardrails

  • Auto-Chaining Captures: Automatically injects VariableCapture(variable_name="product_id", json_path="$.id") on creation steps and wires {{product_id}} into downstream paths and bodies.
  • Regex AST Sampler (sample_from_regex): Parses regular expression ASTs via Python's sre_parse to synthesize valid strings for strict parameter patterns (e.g. ^[A-Z]{2}Z\d{3}$ ➔ AKZ101).
  • 100% Coverage Guarantee: Any endpoint not covered by Gemini is automatically synthesized by the deterministic fallback builder.

🔧 What Self-Healing Fixes

  • Regex & Format Drift: Server rejects zoneId="sample" with regex error ➔ heals to "AKZ101".
  • Missing Required Fields: FastAPI returns 422 loc: ["body", "email"] ➔ synthesizes valid field.
  • Negative Status Alignment: Negative test expects 400, server returns 422 ➔ aligns to 422.

🚫 How We Prevent "Cheating"

  • Happy-Path Protection: apply_test_fix_to_step() strictly forbids changing a 200/201 expectation to 4XX or 5XX on Happy Path tests.
  • 5XX Crash Preservation: Never hides a 500 Internal Server Error—surfaces it as a real API defect.

⚡ Dual-Mode Reliability

  • Primary: Gemini 3.8 Flash inspects the OAS schema, captured context, and HTTP error body.
  • Fallback: Deterministic RFC 7807 parameterErrors & regex AST analyzer works 100% offline.
🎤 Speaker Note: "A key question judges ask is: 'Does self-healing hide real bugs?' No! Our safety guardrail never weakens a Happy Path 2XX assertion into a 4XX/5XX, and never touches 500 server crashes. It only repairs test input drift and immediately re-runs against the live API to prove the fix."

Deep Dive #3: Auditability & DevOps

Provenance Visualizer & Automated GitHub CI/CD

Full transparency into every AI decision, paired with 1-click GitHub branch deployment and automated reporting.

🔍 "Visualize Tests" Provenance Page (ui_visualizer.py)

Engineers never have to trust a "black box." For every generated journey, OASVerify renders:

  • Interactive Mermaid Flowchart: Shows exact step execution order and {{variable}} producer-to-consumer data-flow edges.
  • Source Attribution Badges: Clearly labels whether a journey was "Designed by Gemini" vs. "Deterministic Baseline".
  • Guardrail Audit Log (provenance.py): Lists every deterministic intervention (e.g., body_backfilled, path_chained, captures_added, steps_reordered).
  • Self-Healing Diffs: Displays field-level strikethrough diffs (before ➔ after) and reasoning for every repaired step.

🐙 GitHub Sync & Automated GitHub Actions Pipeline

Seamless transition from interactive exploration to enterprise CI/CD regression suites:

  • Selective Export & Push: Download standalone test_suite.py or push passing tests directly to GitHub via REST API or SSH.
  • Collision-Free Timestamped Folders: Organizes suites under tests/oas-tests-agent/{YYYY-MM-DD_HH-MM-SS}/test_suite.py.
  • Automated GitHub Actions Trigger (run-oas-tests.yaml):
    • Triggers automatically on push to the test branch under tests/oas-tests-agent/**.
    • Executes pytest and publishes a rich Markdown Job Summary Table + downloadable HTML & JUnit XML reports.
